# 添削を反映し、好みを学ぶ

著者は数個のコメントしか書きません。その数個から著者の好みを読み取り、原稿全体と次の草稿に効かせるのが
この skill の役割です。指摘箇所だけを直すと、同じ指摘が次の節でも繰り返されます。

## 手順

1. **コメントを集める。** `pops context` の comments（`%>` 行）と、会話での指摘を合わせて番号を振る。
   `STYLE.md` と共有 STYLE（`paper.toml` の `[style] shared`）を読み、既にある規則を把握する。

2. **各コメントの意図を読み、行き先を決める。** 短いコメント（「長い」「結論を先に」「これは要らない」）は、
   対象の文と前後を読んで、著者が何を不満に思ったかを言葉にする。段落の上の `%>` はその段落全体に、
   行末の `%>` はその文に付いたものとして読む。

   | 種類 | 行き先 |
   |---|---|
   | 主張・発見・節や段落の構成 | 先に `BRIEF.md` を直す（`paper-brief` の「指摘を受けて直すとき」）。それから本文 |
   | 図 | `paper-figure` の「著者の指摘を反映するとき」 |
   | 文章（言い回し、文の順、詳しさ、用語） | 本文を直す |
   | 事実・数値の誤り | source を確かめ、`numbers.tex` と本文を直す |
   | 質問 | 会話で答える。答えが本文に要るなら本文にも書く |

   意図が複数に読め、選び方で原稿が大きく変わるものは著者に尋ねる。それ以外は解釈を選び、報告に書く。

3. **指摘箇所を直す。** コメントの付いていない文章は、著者が読んで受け入れた文章として扱い、
   次の手順で広げる規則が当てはまる箇所のほかは変えない。全体を書き直すと、著者は再び全文を読むことになる。
   - 主張の文から外した条件や留保は、BRIEF の置き場へ移す。置き場の節がまだ無ければ、節を作って書く。
     削っただけにすると、原稿のどこにも条件が残らない。
   - コメントの無い箇所で BRIEF と食い違う文章（載せないものに当たる文など）を見つけたら、変えずに報告で伝える。

4. **好みを規則にする。** コメントごとに、その場限りの修正か、著者の好みかを分ける。
   誤字や数値の訂正は学習しない。好みは次の形の規則にする。

   ```markdown
   - 段落は結論の文で始め、図の紹介から始めない。
     - 例: 「図 3 に圧力分布を示す。下流では…」→「粗い壁の管は圧力損失が 3 倍大きい（図 3）。」
     - 由来: 2026-11-05 results（1 回）
   ```

   - 規則は「こう書く」という行動で書き、例を付ける。著者が直した文があればそれを、無ければ自分が直した
     前後の文を使う。例があると次の草稿で再現しやすい。
   - 置き場所: どの論文にも当てはまる好みは共有 STYLE へ。この論文だけの決まり（用語、記号、節の構成）は
     `STYLE.md` へ。共有 STYLE に書き込めない環境では、`STYLE.md` の「共有待ち」に書いて著者に伝える。
   - 既にある規則と同じ 1 文の行動で言えるなら、新しく足さずに、回数を増やして例を差し替えるか足す。
   - 著者が一般的な好みとして述べたもの、どこにでも当てはまることが明らかなものは、1 回目から規則にする。
     その箇所だけの事情かもしれないものは `STYLE.md` の「候補」に置き、同じ種類の指摘がもう一度来たら
     規則へ昇格する（置き場所は昇格のときに決める）。
   - 新しいコメントが既存の規則と食い違うときは、新しいほうに合わせて規則を書き換え、報告に書く。

5. **原稿全体へ広げる。** 新しく規則にしたもの、昇格したものを、原稿の他の箇所（caption を含む）と図に
   適用する。候補は広げない。どこを規則の適用で変えたかを控えておく。

6. **片付けて build する。** 対応した `%>` 行を消す。判断が要るもの、対応しなかったものは残す。
   一部だけ対応したコメントは、残っている部分だけに書き直して残す。
   `pops build` を通し、節や段落の順・増減を変えた場合は `paper-check` の読者テストを行う。

7. **報告する。** 著者が学習の中身を直せるように、次を短く示す。
   - コメントごとに、どう解釈し何を変えたか。
   - 学習した規則: 新規、昇格、候補。それぞれを書いた file の path（共有 STYLE は Git の外にあるので明示する）。
   - 規則の適用で変えた箇所（file と段落）。
   - 著者の判断が要るもの。同じ内容を `BRIEF.md` の未決にも書く。

   著者が「その規則は違う」と言ったら、規則を消すか直し、広げた変更を戻す。

## STYLE の手入れ

規則が増えると読まれなくなる。1 つの節が 15 個を超えたら、似た規則をまとめ、例を良いもの 1〜2 個に絞る。

## 履歴

添削 1 回分の反映を 1 つの commit にまとめると、著者が round ごとの差分を追える。
commit するかどうかは、著者の指示とこの repository の方針に従う。
