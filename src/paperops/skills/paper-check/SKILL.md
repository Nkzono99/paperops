# 伝わるかを確かめる

書いた本人は主張を知っているので、原稿を読み返しても伝わるかどうかは判断できません。主張を知らない読者に
読ませ、受け取った内容を BRIEF と比べます。正確さの照合は、それとは別の作業として行います。

## 指定 PDF への講評

「この PDF だけ」「詳しすぎる箇所を挙げて」など、仕上がった PDF への助言を頼まれたら、指定 PDF をそのまま読み、
講評を会話で返して終える。下の build、BRIEF との比較、編集・記録は原稿を仕上げる依頼の手順である。
初見の読者に頼む場合も同じ PDF だけを渡す。頼めなければ自分で読み、PDF を読めないときはその旨を伝える。

詳しさを見るときは、主張と決め手になった比較を押さえ、各段落でどこまで読めば判断できるかを探す。
候補を外して読み直し、対照や例外を取り違えずに済むかを確かめて、読解の妨げが大きい順に挙げる。
各指摘には **ページ・節と段落の冒頭、削る範囲、残す根拠とその理由** を添える。圧縮案は短い一文で足りる。
移すのは図注で比較条件を確かめる、付録で手法を再現するなど、移した先に用途がある場合に限る。
例えば改善の要因を切り分ける三条件は残し、すでに図で読める各条件の同じ傾向を一文にまとめる。

## 査読者の基準での講評

「レビューして」「改善案を出して」「投稿できるか見て」と頼まれたとき、査読役の agent を立てるときに使う。
観点を限らずに改善案を挙げさせると、査読を通った論文にも「大修正が必要」と十数件以上の指摘が返り、
直すたびに次の指摘が出る。同じ基準で読ませ、返ってきたものを分け、2 回で終える。

1. **査読者の基準で読ませる。** 初見の agent に PDF だけを渡して、次を頼む。

   ```text
   このファイルだけを読み、投稿先の査読者として、この原稿を通すかどうかを判定してください。
   査読者は、気になる点があっても、主張にとって重要でなければ今後の課題として通します。挙げるのは次の 2 種類だけです。
   - 誤り: 原稿の中で食い違っている式・数値・単位、本文と図、要旨と本文。食い違う両方の記述と場所を示す。
   - 主張が成り立たなくなる疑い: 当たっていたら主張か主要な発見がどう変わるかを、理由つきで 1 文で書けるもの。
     「確かめていない」「示していない」だけのもの、主張の範囲が少し狭まるだけのものは当たりません。
   追加の検証、留保の追記、定性的な記述の数値化、設定の追記、構成、文章は、この 2 種類に当たらない限り挙げません。
   1. この論文の主張を 1 文で。
   2. 誤りと、主張が成り立たなくなる疑いの一覧。無ければ「なし」。
   3. 気になったが通した点を最大 3 つ（査読で聞かれるかもしれない点の控え）。
   ```

2. **返ってきた指摘を分ける。** 観点を限らない講評（別の agent、共著者、著者が持ち込んだもの）も同じ表で分ける。

   | 指摘 | 扱い |
   |---|---|
   | 原稿の中の食い違い | 原稿と出典で確かめ、本当なら直す。残さない |
   | 要旨や結論が、本文の自分の結果と食い違う | 主語か動詞を絞って直す |
   | 主張が成り立たなくなる疑い | `paper-predict` の「上乗せの検証を分ける」の 2 つの問いで分け、著者に伝える |
   | 追加の検証で、当たっていても主張が覆らないもの | 行わない。「行わない検証」に 1 行残す |
   | 留保、数値化、設定の追記、構成、文章 | 著者の STYLE に合うものだけ拾う |

3. **終える。** 食い違いを直し、疑いごとの答え（文を絞る、賭けとして計算に回す、行わない）が決まったら終わり。
   直した版を読ませ直すのは 1 回までで、食い違いと疑いに新しいものが無いかだけを見る。
   判定が「通す」になることや、指摘が出なくなることは待たない。査読を通った論文でも、この基準で疑いが 1〜2 件、
   食い違いが数件挙がる。

## 読者テスト

1. **PDF を用意する。** `pops build` で最新の PDF を作る。

2. **初見の読者に読ませる。** この会話、`BRIEF.md`、`STYLE.md` を見ていない agent（subagent）に、
   `build/main.pdf` だけを読むよう頼み、次を尋ねる。PDF を読めない環境では `manuscript/` の TeX を渡す。
   予想を含む草稿でも同じに行う（色の付いた箇所も、得られた結果として読んでもらう）。

   ```text
   このファイルだけを読んで答えてください。repository の他のファイルは開かないでください。
   1. この論文の主張を 1 文で。
   2. その主張を支える発見を最大 3 つ。それぞれ根拠の図番号も。
   3. 読んでいて主張を見失った箇所、何のための段落か分からなかった箇所（節と段落）。
   4. Abstract だけを読んだ人は、1 の主張を言えるか。
   5. 結果やモデルで詳しさが気になる段落について、何が判断でき、どの文や図で判断が済んだか。
      その後に、判断を変える例外や条件はあったか。
   ```

3. **BRIEF と比べる。**
   - 1 が BRIEF の主張 1 文と同じ意味なら合格。
   - 弱い、または別の点を主張として受け取っていたら、題、Abstract、Introduction の末尾、Discussion の冒頭で
     主張を追えるかを読む。主図と caption では、その主張がどの対象を比べた結果かを特定できるか確かめる。
   - 2 に BRIEF の発見以外が挙がったら、載せないはずの結果が目立っているか、主要な発見が埋もれている。
     分量と位置を直す。
   - 3 で挙がった箇所は、その段落の役割に戻って読み直す。例えば対照が分からないまま結果が続くなら、
     比べる条件を示す一文を結果の前に置く。
   - 5 をその節の意図と比べる。別の判断をしたなら段落の組み方を、対照や例外が伝わらなければ根拠を、
     判断が済んだ後も同じ説明が続くなら終える位置を直す。
   - 読者の 1 文のほうが BRIEF より良い主張に見えたら、原稿を直さずに著者へ伝える。

4. **骨子を比べる。** `pops outline` の出力を BRIEF の段落骨子と並べる。骨子に無い段落、第 1 文から
   役割が読み取れない段落、主要な発見より副次的な結果のほうが分量の多い節を見つけて直す。

5. **直したら、新しい読者でもう一度行う。** 大きく削った版は同じ問いで読み、前回の回答と比べる。
   削ったために説明できなくなった点は元の段落にたどる。例えば符号の理由が失われたら、それを導く一文を戻す。
   前の版から続く疑問は、今回の削除とは別に原因を探す。
   2 回直しても主張が伝わらないときは、文章ではなく BRIEF（主張の立て方、載せるものの選び方）の問題として
   著者に伝える。

subagent が使えない環境では、初見の読者の代わりに `pops outline` の出力だけを上から読み、段落の第 1 文と
caption だけで主張 1 文と発見が言えるかを確かめる。初見の目より甘くなるので、その旨を報告に書く。

## 照合

主張を言い切るぶん、根拠との対応はここで確かめます。食い違いは出典にたどり、数値や文が指す対象を直します。
承認された主張そのものが根拠に支えられていないと分かったら、著者に伝えます。

数値・引用・図と本文の食い違いは、その場で直します。掲載条件に合う系列が欠けていたら、`paper-predict` の
「試行で設定が混在しているとき」に従います。すでに揃った根拠に追加の計算や確認を求める意見は、照合役や初見の読者が
挙げたものも含めて、`paper-predict` の「上乗せの検証を分ける」の 2 つの問いで分けます。主張が覆りうるものは
著者に伝え、賭けとして「これから要る計算」に載せます。主張の範囲を狭めるだけのものは、計算を求めずに
成立条件を直します。残りは「行わない検証」に 1 行残し、追加の計算や確認は求めません。

- **数値**: 議論・限界も含め、計算から得た値を `numbers.tex` にたどれるか。平均、窓ごとの最小・最大、上限など、
  集計の意味が本文の表現と合うか。Abstract と主要な発見の値は出典のファイルを開いて見比べる。
  定性的に述べた傾向は図や元の結果と照合する。読み取りが合えば、その確認に使った値は本文に足さずに済む。
  主計算を入れ替えたときは、旧 run に由来する値を拾い、現在の図や結果を説明する値は採用した run で数え直すか外す。
  比較用に残す値には元の条件を明記する。`\pending` が残っていれば一覧にする。
- **予想**: まだ得ていない結果に基づく数値・文・図に、印（`\pred{}`、`figure.md` の `predicted`、BRIEF の
  `予想`・`一部確認`）が付いているか。根拠が手元に無いのに印の無い記述を見つけたら、根拠を探すか、予想として印を付ける。
  予想そのものは誤りではないので、数を数えて報告に載せる。
- **発見と根拠**: 原稿の文をそのまま読んで、挙げた根拠で言えるかを確かめる。点検で留保を足す前に、
  今の文から読者がどんな誤った結論を引くかを具体化する。同じ結論に着くなら、既にある断りも削れる。
  実測で傾向が逆転する例や、応用の可否が変わる条件は、その箇所を読んで分かるようにする。
- **図**: 本文が図について述べていることが、図から読み取れるか。全ての図が本文から参照されているか。
  `figure.md` の状態が `draft` のままの図は無いか。
- **用語と記号**: 本文で定義した対象と量を、caption と描画済みの図の軸・凡例・注記までたどる。
  同じ対象の別名、同じ記号が別の量を指す箇所、区別した解が図で同じ名前になる箇所を挙げて直す。
- **文献**: 引用した文献が実在し、引用箇所の内容を支えているか。`\note{要出典: ...}` が残っていれば一覧にする。
- **翻訳を照合するとき**: 基準にする版と訳文の対応箇所を文ごとに読み、対象、変化の向き、比較条件、断定の強さを
  照らし合わせる。式や参照番号がそろっていても、「途中で反射する」を「上流へ戻る」と訳すと到達先まで断定してしまう。
  語数制限で要旨を縮めるときも、どの条件で何が起きたかが残る訳にする。
- **build**: `pops build` にエラー、未定義の参照と引用が無いか。
- **内部名**: run id、script 名、directory 名、作業中の呼び名が本文と図に出ていないか。

## 報告

読者が受け取った主張 1 文、BRIEF との違い、直した点、照合で見つけた食い違い、発表までに残っているもの
（残っている予想の数、賭け、主張が覆りうる弱点）、著者の判断が要る点を短く伝える。
直さずに残した問題は `BRIEF.md` の未決に書く。
