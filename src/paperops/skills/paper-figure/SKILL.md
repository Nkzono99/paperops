# 図を作り、推敲する

最初に出てきた図は下書きです。script が動いたことと、図が読者に伝わることは別なので、描画結果を
自分の目で見て直す round を必ず回します。図 1 枚は `figures/<name>/` にまとめます。

```text
figures/<name>/
├── figure.md     メッセージ、比較、データ、推敲記録
├── make.py       縮約データを作り、図を描く
├── data/         縮約データ（図に必要な分だけ）、予想の図では予想の data
├── <name>.pdf    原稿用
└── <name>.png    確認用（掲載寸法）
```

## 手順

1. **`figure.md` を先に書く。** `figures/_template/` を `figures/<name>/` に複製し、メッセージ（1 文）、
   読者にさせる比較、支える発見（BRIEF の C1 など）、データの出典、掲載幅を埋める。
   メッセージが 1 文で書けない図は、分けるか、BRIEF の図の割り当てを見直す。

2. **データを縮約する。** `make.py` の `reduce()` が source から読み、図に必要な配列だけを `data/` に保存する。
   source の場所は `common.source("<name>")` で引く。run は run id で特定し、出典を `figure.md` に書く。
   run の出力を直接読む処理は重いので、計算機の決まりに従って計算ノードで実行する。
   縮約データがあれば、見た目の調整は手元ですぐ繰り返せる。

3. **描く。** `common.use_style()` を使い、掲載寸法（`common.SINGLE` / `common.DOUBLE`）で描き、
   `common.save(fig, __file__)` で保存する。Python は project の `.venv` を使う
   （無ければ `uv venv` と `uv pip install matplotlib numpy` で作る）。

4. **見て直す。** `<name>.png` を画像として開いて見る。下の観点を上から順に確かめ、問題を直して描き直す。
   これを 1 round として、`figure.md` の推敲記録に `- R1: 見つけた問題 → 変えたこと` と 1 行で残す。
   直すところが見つからなくなるまで続ける（少なくとも 2 round、多くて 5 round）。

   1. **メッセージ**: 5 秒見て、`figure.md` のメッセージが言えるか。読者にさせる比較が、図の中で
      いちばん目立つ要素になっているか。主役の系列には強い色と太い線を使い、脇役は灰色や細い線に落とす。
   2. **取捨**: メッセージに要らない panel、系列、注記、目盛を除く。1 枚の図に 1 つのメッセージ。
   3. **比較のしやすさ**: 見比べるものは同じ軸の上か隣り合う panel に置き、軸の範囲を揃える。
      対数か線形か、軸の範囲、色の割り当て（量の大小は連続的な配色、正負は 0 を中心にした配色）が
      メッセージに合っているか。
   4. **掲載寸法での読みやすさ**: 文字が小さすぎないか（印刷で 7 pt 以上）、線や点が潰れていないか、
      label や凡例が data に重なっていないか、目盛が多すぎないか。凡例より、線のそばに直接書く名前のほうが読みやすい。
   5. **言葉**: 軸 label に量の名前と単位があるか。系列名は本文と同じ公開用の呼び名か
      （run id や変数名のままになっていないか）。panel には (a), (b) を付ける。
   6. **図どうしの統一**: 同じ量・同じ条件には、全ての図で同じ色・記号・呼び名を使う。
      対応は `STYLE.md` の「図」に書いておく。
   7. **誠実さ**: 軸の切り方や配色が差を誇張していないか。主張が不確かさに左右されるなら、ばらつきを描く。

5. **初見の目で確かめる。** この会話と `figure.md` を見ていない agent（subagent）に PNG だけを渡し、
   「この図から読み取れることを 1 文で。分かりにくい点はどこか」と尋ねる。答えがメッセージと違えば、
   もう 1 round 直す。subagent が使えない環境では、caption を隠した状態で自分に同じ問いを立てる。

6. **caption を書く。** 第 1 文でメッセージを言い、次に何が描かれているか、最後に条件を書く。
   本文からは、図を紹介する文ではなく、主張の文の根拠として参照する（「…3 倍大きい（図 2）」）。

7. **状態を進める。** 推敲が済んだら `figure.md` の状態を `reviewed` にして著者に見せる。
   その際、推敲で何を変えたかを 2〜3 行で伝える。著者が了承したら `approved` にする。

## 著者の指摘を反映するとき

指摘された図を直したら、同じ指摘が当てはまる他の図も直す。指摘が見た目の設定（文字の大きさ、色、線の太さ、
余白）なら `figures/paper.mplstyle` か `figures/common.py` に入れ、全ての図を描き直す。設定に落とせない好み
（panel の並べ方、注記の入れ方）は `STYLE.md` の「図」に規則として書く。学習の手順は `paper-revise` に従う。

## 予想の図

結果がまだ無い図は、予想で描く。図があると、論文の流れと、その図を得るために要る計算がはっきりする。

- `make.py` の `PREDICTED` を `True` にし、`predict()` に予想の根拠（見積もりの式、既にある run からの外挿）を
  code として書いて `data/predicted.npz` を作る。根拠が code になっていれば、著者が予想の出どころを確かめられる。
- `common.mark_predicted(fig)` が図に PREDICTED の印を入れる。`figure.md` の状態は `predicted` にし、
  データの節に根拠を書く。
- メッセージ、比較、見た目の推敲は、実際の data の図と同じに行う。結果が出たとき、data を差し替えるだけで済む。
- 結果が出たら `PREDICTED` を `False` にして `reduce()` で実際の data を読み、予想と見比べる。
  状態を `draft` に戻して推敲し直す。予想と違っていたら `paper-predict` の「結果が出たら」に進む。

## 模式図

概念や配置を示す模式図も、同じ手順で下書きを作る。模式図は仕上がりの差が出やすいので、下書きであることを
著者に伝え、著者が描き直す場合の元になるよう、要素と配置の意図を `figure.md` に書いておく。
