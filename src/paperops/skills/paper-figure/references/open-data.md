# 図を再現する公開データを用意する

論文の図と主要な数値を、読者が手元で描き直せる一式にまとめる。著者から、公開データの用意や Zenodo などへの寄託を
頼まれたときに使う。目標は、配布物を展開した別の場所で、同梱したデータと README に書いた依存だけを使って
図が描き直せることである。研究用の directory や非公開の code を読む処理が 1 つでも残ると、手元では動いても
読者の環境では動かない。

## 置き場所と範囲

- 置き場所は、論文 project の直下の `open_data/` を既定にする。著者の指定や既にある置き場所があれば、それに従う。
  論文と同じ repository に置くと、図を直したときに公開データも直す必要があることに気づける。
- 対象にする図と数値は、`BRIEF.md` の図の割り当て、`manuscript/numbers.tex`、各図の `figure.md`、それに著者の依頼から選ぶ。
  確認のためだけの計算や、論文で使わない枝の結果は含めない。範囲を広げるほど、確かめる量と説明する量が増える。
- 生の出力、restart 用の checkpoint、認証情報、cache、手元の下書き、絶対 path、symbolic link は入れない。
  link や絶対 path は、展開した先では何も指さない。

## 描画を縮約から切り離す

`figures/<name>/make.py` は、`reduce()` が source から縮約データを作り、描画は `data/` にあるその縮約データだけを
読む構成になっている。公開用の script は、この描画の部分だけで作る。

- `figures/<name>/data/` の縮約データを `open_data/data/` に複製し、描画の code を `open_data/scripts/` に移す。
  `reduce()`、`common.source()`、run の出力を読む処理は持ち込まない。これらは公開しない source を前提にしているため、
  読者の手元では動かない。
- `figures/common.py` と `figures/paper.mplstyle` のうち描画に使う部分も、`scripts/` に複製する。
- 縮約データが npz のように中身の見えない形式なら、key・形・単位の一覧を添える。読者が配列の意味を
  code から読み解かずに済む。
- 縮約が描画と分かれていない図は、先に論文側の `make.py` を `reduce()` と描画に分け、論文の図が変わらないことを
  確かめてから公開用に移す。

## 一式の中身

```text
open_data/
├── README.md     何のデータか、図と data の対応、描き直す手順、全部を計算し直すときの道筋、問い合わせ先
├── data/         縮約データと、ファイルと図の対応表（出典の run id や観測 id、単位、座標、範囲、前処理）
├── scripts/      描画の code、依存と版の一覧（requirements.txt など）
└── inputs/       計算に使った入力ファイル（分かる範囲で restart 元も）
```

- README には、同梱のデータで図を描き直す手順を command で書く。全部を計算し直すには何が要るか
  （公開している solver の URL と版、非公開の code なら入手の問い合わせ先）も書く。読者がどこまで自分で
  たどれるかを、最初に判断できるようにする。
- 論文の図の PNG を確認用に入れてもよい。モデルの仮定の説明や形式証明など、論文が依っている他の資料は、
  著者が含めると決めたときに、使い方と検証の command を添えて足す。

## 権利と寄託の情報

- 観測データや他者のデータを含むときは、再配布してよいかを確かめる。再配布できない一次データは入れず、
  出典と入手の手順を README に書く。
- 題、著者と ORCID、license、引用の書き方、関連する論文の DOI のように、まだ決まっていない寄託の情報は、
  配布物の外のメモ（例: `open_data/DEPOSIT.md`。アーカイブには入れない）にまとめる。決まっていない値を
  データの中に書くと、決まったときに直し漏れる。
- 権利の条件、embargo、license の選択、upload と公開は著者が決めて行う。agent は候補と未決の項目を並べて渡す。
  Zenodo の入力項目は公式の案内で確かめる。[Zenodo の upload の案内](https://help.zenodo.org/docs/deposit/create-new-upload/)

## アーカイブと検証

- 外部に寄託するときは、`SHA256SUMS` を付けて配布用のアーカイブを作る。アーカイブ、展開して描き直した出力、
  build の副産物は `.gitignore` に入れる。どれも一式から作り直せるので、repository に入れると古い版が残るだけになる。
- アーカイブを論文 project の外の空の directory に展開し、README の手順のとおりに環境を作って、対象の図を全て
  描き直し、主要な数値を集計し直す。元の図や数値と照合し、許容幅を使って一致を判断したときはその幅も記録する。
  手元の directory で動かすだけでは、持ち込み漏れや絶対 path が見つからない。
- checksum と README のリンクも確かめる。確かめられなかった範囲と失敗した箇所は、`LOG.md` と著者への報告に書く。
