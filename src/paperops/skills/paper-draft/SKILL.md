# 草稿を通して書く

BRIEF が決まっていれば、図から PDF までを著者の手を借りずに作ります。著者が見るのは、できあがった PDF と
骨子です。途中で判断に迷う点は推奨案で進め、最後にまとめて伝えます。

## 手順

1. **状況を読む。** `pops context`、`BRIEF.md`、`STYLE.md`、共有 STYLE（`paper.toml` の `[style] shared`）を読む。
   BRIEF に主張 1 文が無ければ `paper-brief` から始める。状態が `予想` の発見は、`paper-predict` に従って
   図・数値・本文に入れる。

2. **図を先に作る。** BRIEF の図の割り当てに沿って、`paper-figure` で主図を作り推敲する。
   Results で読者が確かめることを決め、根拠になる図・表・事例と対応させる。

3. **数値を `manuscript/numbers.tex` に集める。** 本文に出す数値をマクロにし、出典（source 名、run id、
   解析の path、script）と、集計値なら何をどう集計したかを上のコメントに書く。値は source のファイルを開いて確かめる。
   まだ得ていない値は、予想の値を `\pred{}` で書く。予想も立てられない値だけを `\pending` にする。

4. **本文を書く。** `manuscript/sections/<name>.tex` を作り、`main.tex` から `\input` する。
   順番は Results → Methods → Discussion → Introduction → Abstract・題・Conclusion。
   先に書いた節が、後の節で何を約束し何を説明すべきかを決める。
   各段落は BRIEF の段落骨子の第 1 文から書き始める。結果・モデルでは、その節で読者にしてほしい判断から
   必要な材料を選ぶ。既存の骨子でも、第 1 文だけで選べるならそのまま書ける。段落の間は空行 1 つで区切る。

5. **文献を入れる。** 実在を確認できた文献（DOI、出版社のページ、source project の文献 list）を
   `refs.bib` に入れて引用する。確認できないものは `\note{要出典: 何を支える文献か}` にして、著者に任せる。

6. **build する。** `pops build` を実行し、エラー、未定義の参照と引用を無くす。

7. **確かめて直す。** `paper-check` の読者テストと照合を行い、見つかった問題を直す。

8. **著者に渡す。** 次を短く伝える。
   - PDF の場所と、`pops outline` の出力（骨子）。
   - 読者テストの結果: 初見の読者が受け取った主張 1 文。
   - 予想で書いた発見と、発表までに要る計算（`paper-predict` の表）、行わないと決めた検証。
   - 著者の判断が要る点を 5 件以内で（推奨案を添える）。同じ内容を `BRIEF.md` の未決にも書く。
   - 添削の入れ方: TeX に `%> コメント` を書くか、会話で伝える。

## 書き方

主張が伝わる文章にするための原則です。STYLE に著者の規則があれば、そちらを優先します。

- **結果の段落は、何が分かったかを先に書く。** 複数の条件を一枚の図で比べる節では、最初に何と何を
  どの量で比べるかを一文で示すと、続く結果を読みやすい。対照と変更後の条件を読者が続けて比べられる順に置く。
- **主張の文は言い切る。** 主要な発見には決め手となる対照・観察・図表を示し、成立条件は BRIEF で決めた置き場に
  一度だけ書く（置き場の節がまだ無ければ、その節を先に作る）。
  条件や留保を文ごとに付けると、どれが主張かが読者に見えなくなる。正確さは置き場と `numbers.tex` が守る。
  別の箇所でその条件が読みに要るとき（単独で読まれる caption、別の判断に使う段落）は、説明を繰り返さず、
  要る条件だけを一言で呼び戻す。
  修飾を残すかどうかは、外したときに読者の持ち帰る結論が変わるかで決める。

  ```text
  前: 本研究で用いた条件の範囲において、粗面管の圧力損失は、流れが乱流である場合に、
      滑面管と比較して約 3 倍程度に増加する傾向が見られ、これは壁面近傍の乱れに起因する可能性が示唆される。
  後: 粗い壁の管は、滑らかな管より圧力損失が 3 倍大きい（図 2）。凹凸が壁の近くの流れを乱すためである。
      この差は、流れが乱流になると現れる。
  ```

- **主張を支える根拠を前に出す。** 得られた結果のうち、主張を補強するものを選んで本文と図の中心に置く。
  主張と関係の薄い結果は載せないか付録に回す。主張の範囲を狭める事実や、合わなかった条件は、限界の段落に
  一度、具体的に書く。選んで見せることは論文の書き方の一部であり、結果を消す、値を変える、行っていない確認を
  行ったと書く、といったこととは別である。
- **Results は、読者が証拠から一つの判断を下せるところまで書く。** 差を説明するなら決め手になった対照を、
  過程を示すならどこで何が起きたかを、未検出なら観測が許す範囲を残す。図表や事例からその判断ができた所で
  段落を閉じる。次の文を外すと傾向の例外や異なる説明が見えなくなるなら、その文には役目がある。
- **モデル説明は、読者が結果の生じ方をたどれるところまで書く。** 与えた条件から何が決まり、観測や評価に使う量を
  どう作ったかを示す。操作を外すと結果の意味が変わる箇所は本文に置く。導出自体が貢献なら読者が検算できるところまで示す。
  詳しさに迷ったら、[結果とモデル説明の手引き](references/results-and-model.md)で段落の問いに合う型を選ぶ。
- **紙面は重要度に比例させる。** 主要な発見に段落と図を使う。副次的な結果は判断に効くものだけ短く残す。
  `pops outline` の分量表示で、発見ごとの配分を確かめる。
- **Introduction の最後で、何を示すかを結果まで言う。** 「〜を調べる」で止めず、わかったことを 1〜2 文で書く。
  Abstract と Discussion の最初の段落にも、BRIEF の主張 1 文と同じ内容が現れるようにする。
- **同じものは同じ語で呼ぶ。** 用語は初出で決めて `STYLE.md` の「用語と表記」に書き、以後は変えない。
  新しい複合語を作るより、普通の言葉で 1 文書く。
- **具体的な主語と動詞で書く。** 「圧力損失の増加が見られる」より「圧力損失が増える」。
- **結果がまだ無い所も、最後まで書く。** 予想の結果、その解釈、論文にとっての意味を完成形の文で書き、
  `\pred{}` で印を付ける。分かっていることだけで節を閉じると、論文全体の流れを著者が確かめられない。
- **読者の言葉で書く。** run id、script 名、directory 名、作業中の呼び名は、本文と図に出さない。
  執筆上の予定や保留は本文に書かず、`LOG.md` か `\note{}` に置く。
- **caption は第 1 文で図のメッセージを言う。** 続けて、何が描かれているか、条件の順に書く。

## 節を足す・書き直すとき

一部だけを書く依頼でも、BRIEF の段落骨子の該当箇所を確認し、骨子を変える必要があれば先に BRIEF を直す。
著者が既に見た節を書き直すときは、著者が受け入れた文章を保ち、頼まれた範囲だけを変える。
