# 主張を決める

結果を正確に並べただけの原稿は、何を言う論文かが読者に伝わりません。先に「読者が読後に言える 1 文」を決め、
その 1 文に役立つものだけを載せます。何を選び何を捨てるかは著者の判断なので、ここが著者との共同作業の中心です。
ここが決まれば、本文は BRIEF に従って書けます。

## 手順

1. **材料を集める。** `pops context` で source と解析 topic を確認し、各 source の `LOG.md`、`notes/`、
   解析 topic の `README.md` と `out/` の小さな縮約出力を読む。runops project では、その directory で
   `runo context`（読むだけの command）を実行すると run の状態と要約も読める。著者が会話で述べた狙いは、
   ファイルの記述より優先する。得られた結果を「わかったこと / 根拠の場所 / どのくらい確かか」の短い一覧にして、
   会話で示す。先行研究は、内容を確認できた範囲で「これまで」に書き、確認できていない点は未決に置く。

2. **主張 1 文の候補を 2〜3 個作る。**
   - 結果を述べる文にする。「〜を調べた」「〜を明らかにする」ではなく「〜は〜である」「〜が〜を決める」。
   - 候補は強さと範囲を変える: 最も強く言える版、範囲を絞って確実な版、切り口を変えた版。
     安全で全部を含む 1 文は、たいてい何も言っていない。強い版を必ず 1 つ入れる。
   - 候補ごとに、支える根拠と、足りない根拠を 1〜2 行で付ける。
   - 良い 1 文の目安: 分野の研究者が聞いて「何がわかったのか」を言い直せる。反対の主張に意味がある。
     日本語で 60 字、英語で 25 words ほどに収まる。
   - 推奨する候補と、その理由を添える。推奨案が、どちらに転ぶか分からない予想（賭け）に依っているときは、
     どこが賭けかと、外れた場合に残る主張も添える（`paper-predict`）。

3. **著者に選んでもらう。** 候補を会話で見せる。著者の言い換えや別案が出たら、それを採用する。
   「任せる」と言われたら推奨案で進め、選んだ理由を `LOG.md` に書く（BRIEF の状態は `draft` のまま）。

4. **主要な発見を 2〜4 個に絞る。** 主張 1 文を支える柱で、発見ごとに次を書く。
   - 言い切り文: 本文の段落の第 1 文にそのまま使える短さで。
   - 状態: `確認済み`（根拠が手元にある）、`予想`（これから得る）、`一部確認`（一部が手元にある）。
   - 根拠: 図、数値、出典（source 名、run id、解析の path）。
   - 成立条件と置き場: 条件・例外・不確かさと、それを書く場所。

   ```markdown
   ### C1 粗い壁の管は、滑らかな管より圧力損失が 3 倍大きい
   - 状態: 確認済み
   - 根拠: 図 2、\lossRatio（pipe_flow, runs/roughness-scan/_analysis/pressure）
   - 成立条件と置き場: 乱流のときに現れる（結果の直後に 1 文）。粗さの形は 1 種類（Methods と限界の段落）
   ```

   言い切り文と条件を分けて持つことで、本文の主張文を短く保ったまま、正確さを置き場で守れる。

   主張に必要な結果がまだ無いときは、その発見を外さずに `予想` として載せる。手元の結果で言えることだけで
   発見を組むと、論文の筋が結果の在庫に縛られる。予想の立て方と書く項目は `paper-predict` に従う。

5. **載せないものを決める。** 主張に効かない結果を、行き先（付録 / 別の論文 / 載せない）と理由つきで
   「載せないもの」に書く。得られた結果を全部載せると主張が埋もれるので、削ることが主張を見えるようにする
   いちばん大きな操作になる。迷うものは載せない側に置き、著者に見せる。

6. **図を割り当てる。** 発見 1 つに主図 1 枚を基本にし、図ごとにメッセージを 1 文で書く。
   図を順に見るだけで論文の筋が追える並びにする。

7. **段落骨子を書く。** section ごとに、各段落の第 1 文（その段落の主張）を番号付きで並べる。
   - Introduction: 何が問題か → 何がわかっていないか → 本研究が何を示すか（結果まで言う）。
   - Results: 発見の順に並べる。作業した順や run の順ではなく、読者が納得する順。
   - Discussion: 最初の段落で主張を言い直す → 機構と意味 → 先行研究との関係 → 限界（成立条件の置き場）。
   - 骨子だけを上から読んで、主張 1 文に至る筋が追えることを確かめる。追えない段落は、役割を決め直すか削る。

8. **著者の判断が要る点を未決に書く。** 1 件 1 行で書く。まだ無い根拠は、未決ではなく `予想` の発見として
   書き、要る計算を「これから要る計算」に並べる。予想も立てられないものだけを未決に置く。

9. **承認を得る。** 会話では、主張 1 文、発見、載せないもの、図の一覧、未決だけを短く見せる
   （BRIEF 全文は貼らない）。予想の発見は、予想であることと確信度が分かるように見せる。
   著者が了承したら状態を `approved` にする。

## 指摘を受けて直すとき

主張・発見・構成に関わる添削は、本文より先に BRIEF を直す。本文だけを直すと、次に書き直したときに元へ戻る。
`approved` の BRIEF の主張・発見・載せないものを変えるときは、何をどう変えるかを著者に示して確認する。
段落骨子、図の割り当て、未決は、確認を待たずに直して報告する（置き場になる節を骨子に足す場合を含む）。
変えたら、影響する段落骨子と図の割り当ても合わせて更新し、`paper-draft` か `paper-revise` で本文に反映する。
