# 1.0.0 typed authority migration

## 新規project

`pops init <path>`は六モデルを`v2-authoritative`で初期化する。`--authority legacy`、legacy card directory、workflow macro-state、submission ledgerは新規scaffoldに存在しない。通常のmodel更新はignoredなchange requestを作り、`pops change plan`、`diff`、`apply --yes`へ委譲する。

## 既存project

`pops setup`と`pops update-paperops`は既存の`_paperops/claims/`、`evidence/`、`review/`、`requests/`、workflow state、submission ledgerを削除せず、authorityを自動変更しない。先にmanaged schema/checker/skillを更新し、次の順でshadowを確認する。

```sh
pops model status all
pops model diff research
pops model adopt research --yes
# Editorial / Results hierarchy → Manuscript → Issue → Publication の順に反復
pops workflow migrate diff --json
# reportを確認してadopt planを作り、workflow apply --yes
```

各adoptはsnapshot/journalを持ち、`pops model rollback`または`pops workflow rollback`で戻せる。移行後もlegacy artifactは自動削除されない。内容と履歴を確認して不要と判断した場合だけproject側で別途整理する。

## 互換境界

- 保持: legacy inventory/adapters、migration report、adopt/rollback、living TeX直接編集。
- 削除: 新規scaffoldのlegacy starter、legacy init option、通常checker/skillのlegacy fallback。
- 禁止: model/index/hash/manifest/journalの手編集、legacyへのdual-write、推測によるdelete cascade。
